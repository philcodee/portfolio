The Setup

Context

CivicGuide is a single-page web app that walks users through completing government forms using AI — upload a document, let the model read it, fill in what it knows, and let the user confirm the rest.

Role & Stack

Role: Designer and developer — UX, architecture, full front-end build.
Stack: Vanilla JS · Gemini API · Supabase · Netlify. No framework.
Duration: 6 weeks, April 2026.

The Problem

Field labels like topmostSubform[0].Page1[0].f1_01[0] are common. Instructions reference sections users can't find. The result: people abandon forms, submit them wrong, or pay someone to do what they're entitled to do themselves.

The goal wasn't to replace the form. It was to put a translator between the government's document and the person who needed to complete it.

Three failure modes the design needed to address
  • Illegibility — field labels that don't tell you what to enter
  • Context loss — no signal about why a field exists or what format is expected
  • Abandonment — no save state means any interruption resets progress to zero

The Insight That Drove Everything

The first version asked users to select their civic domain before uploading. It made sense architecturally — and no sense to users. The real insight: the document already knows what it is. Domain became an output of the scan, not an input to the wizard.

Before — domain-first flow
  1. Select your civic domain
  2. Choose your document type
  3. Upload your form
  4. Fill fields
After — document-first flow
  1. Upload your form
  2. AI reads and identifies it
  3. Confirm what it found
  4. Fill the fields it couldn't pre-fill

Key Decision 01

Two scan paths instead of one

Most government PDFs have machine-readable AcroForm fields — sending them to a vision model is wasteful. PDF.js extracts fields locally, then a text-only Gemini call handles classification. Vision scan is reserved for flat or scanned PDFs only.

  • AcroForm path: ~1 second, no image upload
  • Vision path: ~8–30 seconds, retry countdown on overload

Key Decision 02

An agent that narrates instead of asks

Users don't want a conversation about their form — they want to complete it. CivicGuide's agent opens each phase with a typed brief, then recedes. No input field. No thread. Role progression (Router → Domain Expert → Document Agent) gives a consistent mental model without exposing complexity.

Key Decision 03

Form state that survives real life

Any interruption used to mean starting over. After scan, all field data and values are persisted to Supabase. On return, a restore screen names the saved doc type and picks up exactly where the user left off.

  • Save triggers: scan confirm, each fill group, advance to review
  • Restore: resumes at the correct phase and fill group
  • Account panel: all saved forms; per-row continue and delete

Key Decision 04

UX principles as a recurring audit, not a checklist

Five principles — Latency Tolerance, Capability Discovery, Trust Calibration, Transparency, Memory Awareness — were audited at every build session. Each audit named specific gaps; those gaps became the next session's work.

  • Latency Tolerance: "Found N fields — reading the form…"
  • Trust Calibration: Verify badge on low-confidence field hints
  • Memory Awareness: "We pre-filled N fields from your profile"
Principle Gap identified Feature shipped
Latency Tolerance AI processing felt like a black box Named status messages: "Found N fields — reading the form…"
Trust Calibration Users had no way to judge AI accuracy Per-field confidence score · Verify badge on low-confidence hints
Memory Awareness Pre-filled fields weren't distinguished from blank ones "We pre-filled N fields from your profile" note at Phase 3, Section 1
Capability Discovery Users didn't know what the AI could and couldn't do Agent role progression: Router → Domain Expert → Document Agent
Transparency Scan path (fast vs. vision) was invisible Scan tip bar naming the active path and its expected duration

Outcome

What shipped

A fully deployed civic form wizard, tested against the NY State MV-82 registration form. The AcroForm + vision hybrid resolved Gemini's multimodal reliability problems under load — most PDFs take the fast path; the vision fallback has graduated retry logic throughout.

What it demonstrated

The strongest validation was the simplest: in testing, users never asked "what should I upload?" They uploaded what they had. The recurring audit practice kept trust calibration and memory visibility on the table when engineering pressure would have deferred them.
