# Session Log — 2026-06-15
## Biome Box Case Study — Mobile Overlay Debugging

### What we were working on
Fixing the "expand to fullscreen" overlay for the live p5.js UI embed in `biome-box/biome-box-case-study.html`. Three problems persisted across the session:

---

### Problem 1 — Gray bar visible at top of expanded overlay
**Root cause (suspected):** `#ui-wrap` lives inside `.snap-section.section#assets`, which has `data-animate` and scroll-snap properties. These can create ancestor stacking contexts or containing blocks that trap `position: fixed`, meaning the overlay doesn't actually cover the full viewport — the `site-nav` (z-index: 200, background: var(--gray-mid)) bleeds through above it.

**Fixes attempted:**
1. Added `z-index: 9999` to `#ui-wrap.is-expanded` — didn't fix it
2. Hid `site-nav` and `.dot-nav` via JS on expand — didn't fix it (the element was still inside the trapped stacking context)
3. Teleported `#ui-wrap` to `document.body` on expand (using a comment-node anchor to restore position on close) — **not yet confirmed working**

**Current state:** Unresolved. The DOM teleport approach is in place but untested on device.

---

### Problem 2 — Canvas not filling the expanded iframe
**Root cause:** `windowResized()` exists in `sketch.js` and correctly recalculates canvas size — but iOS Safari does not reliably fire a `resize` event inside an iframe when the parent container changes size via CSS. The canvas was sized at page load and never re-measured.

**Fix applied:** Added `{ type: 'resize' }` postMessage in the case study JS, sent 100ms after expand and close. In `sketch.js`, the `message` listener now calls `windowResized()` when it receives this message.

**Current state:** Fix is in but not confirmed working on device.

---

### Problem 3 — Sound requires two taps on iOS
**Root cause:** iOS Safari suspends the Web Audio API `AudioContext` until an explicit `.resume()` call within a user gesture handler. The first `pointerdown` triggered `handlePress` → `sound.loop()`, but the AudioContext was still suspended so the sound was queued. Second tap found it running.

**Fix applied:** Added `try { getAudioContext().resume(); } catch(_) {}` at the top of the `pointerdown` handler in `sketch.js`, before `handlePress` is called.

**Current state:** Fix is in, not confirmed on device.

---
