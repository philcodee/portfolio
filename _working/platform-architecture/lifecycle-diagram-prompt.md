# Claude Code Prompt — Policy Life Cycle Diagram

---

Build a Policy Life Cycle diagram as a standalone HTML component.
Use the existing CSS file already in the project — do not add new styles unless something is explicitly missing.

---

## What to Build

A linear flow diagram showing the three stages of a commercial trucking insurance policy life cycle:

**Submission → Quote → Policy**

Each stage has sub-statuses that branch from it. Some statuses are terminal (the record goes no further). Some are transitional (the record moves to the next stage). Make this distinction visually clear.

---

## Stage 1 — Submission

Entry point. Created when an agent initiates a New Quote.

Sub-statuses:
- **Pending** — Application in progress. Agent can return and resume.
- **Declined** — Terminal. Ineligible submission. Includes declines generated by the Pre-Submission Form.

Transition to Stage 2: A Pending submission that completes the application becomes a Quote.

---

## Stage 2 — Quote

The application has been submitted and priced.

Sub-statuses:
- **Bindable** — Agent can proceed to bind. Active sales stage.
- **In Review** — Underwriting review required. Triggers a system notification on entry and exit.
- **Not Taken Up** — Terminal. The insured declined the quote.
- **Expired** — Terminal (with exception). 30-day validity lapsed. Can be copied to create a new submission.

Transition to Stage 3: A Bindable quote that is bound becomes a Policy.

---

## Stage 3 — Policy

A bound quote. The active insurance contract.

Sub-statuses:
- **In-Force** — Active policy. Endorsement count displayed for context.
- **At-Risk** — Compliance or non-pay issue flagged.
- **Pending Cancellation** — NOC issued. Includes NOC issuance date and reason.
- **Cancelled** — Terminal. Reinstatement request available.
- **Upcoming Renewal** — Policy within 60 days of expiration. Triggers renewal workflow.

---

## Diagram Logic

- The three stages (Submission, Quote, Policy) should read as a clear left-to-right or top-to-bottom primary flow
- Terminal statuses should visually read as exits from the flow — not continuations
- In Review (Quote stage) should read as a pause/hold state, not a terminal
- Upcoming Renewal (Policy stage) should loop back or indicate continuation, not an exit
- Notification triggers should be marked on: In Review (entry/exit), Bindable, Declined, Cancellations, Messages Received — use a small consistent indicator, not a tooltip

---

## Constraints

- Use existing CSS variables and classes — match the visual language already established
- No new typefaces, no new color tokens unless a status requires a semantic color not already defined (e.g. a warning state for At-Risk)
- The diagram should be readable at a single viewport width — no horizontal scroll
- Accessible: status labels should not rely on color alone to convey meaning
